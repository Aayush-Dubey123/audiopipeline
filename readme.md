# AI Voice Studio — Free AI Voice Cloning & Conversion

## 1. Project Overview

AI Voice Studio is a free-to-use, web-based AI audio generation platform. Users can enter text or upload/record an existing voice recording, select a target voice from a built-in library or provide an authorized reference recording, and generate audio in the selected voice.

The objective is to make voice generation and conversion accessible through a simple, modern website without requiring users to install AI models, configure API keys, or understand machine learning.

The project will use open-source voice models and free-tier services wherever practical. It is a personal learning and experimentation project initially, with the architecture designed to support public access later.

**Core promise:** Choose a voice, provide text or audio, generate speech, listen, and download.

## 2. Core Features

### A. Text-to-Voice Generation

Users should be able to:

- Enter or paste a script into a text editor.
- Select a voice from the available voice library.
- Upload a suitable reference recording when supported.
- Choose supported language and available generation settings.
- Generate audio from the text.
- View generation progress and understandable error messages.
- Play, replay, and download the generated audio.

**AI pipeline:** Text input → Base text-to-speech model → OpenVoice voice-tone conversion → Audio output.

OpenVoice V2 is intended to transfer the characteristics of a reference speaker onto speech generated by a compatible base TTS model. It is not a universal model that automatically reproduces every person's voice from text alone.

### B. Voice-to-Voice Conversion

Users should be able to:

- Upload an audio file or record speech using their microphone.
- Select an available target voice model.
- Convert the source speech into the target voice.
- Listen to the source and converted audio.
- Download the result.

**AI pipeline:** Input recording → Audio validation and preprocessing → RVC voice-conversion model → Output audio.

RVC generally requires a compatible target voice model. A reference recording alone does not automatically create a fully trained RVC model.

### C. Voice Library

Create a centralized library of voices available to users.

Each voice entry should contain:

- Unique voice ID and display name.
- Voice description and intended style.
- Supported languages, where verified.
- Model type: OpenVoice reference voice or RVC conversion model.
- A sample audio preview.
- Model location or reference-audio location.
- Model license and usage-permission information.
- Availability status and any limitations.

The library can begin with a small collection of authorized voices. It should expand only as additional models are tested for quality, compatibility, licensing, and performance.

Do not assume every voice model works with both pipelines.

### D. Custom Reference Audio

Allow users to provide an audio reference for a voice they own or are authorized to use.

The application should validate the audio format, duration, size, and basic quality before processing. It should provide clear guidance when the recording is unsuitable.

OpenVoice can use reference audio for voice-tone transfer. RVC normally needs a compatible trained target model, so these two custom-voice workflows must remain distinct in the UI and backend.

### E. Audio Studio

Provide a common output experience for both workflows:

- Audio playback.
- Source-versus-output comparison for voice conversion.
- Generation status and error messages.
- WAV output initially, with MP3 export where supported.
- Download controls.
- Temporary generation history during a session.
- Automatic cleanup of temporary files.

Generated audio should be clearly labeled as AI-generated or AI-converted.

### Backend

- Python

Responsibilities:

- Manage generation requests.
- Select and invoke the appropriate AI pipeline.
- Return job status and audio results.
- Enforce file limits and usage quotas.
- Protect model access and API credentials.

### AI and Audio Processing

**OpenVoice V2:** Primary candidate for reference-based voice-tone conversion in the text-to-speech pipeline. It must be paired with a compatible base TTS model.

**RVC:** Primary candidate for converting existing speech into a compatible target voice.

**Audio utilities:** Use appropriate Python audio-processing libraries for format conversion, resampling, duration checks, and output handling.

**Optional language services:** Gemini, Groq, and OpenRouter may be used for supported tasks such as script cleanup, text processing, or transcription. These services are optional and are not the core voice-generation engines.

All model versions, dependencies, licenses, and supported languages must be verified during implementation.

## 4. System Architecture

The application consists of five logical components.

1. **Web client:** Collects user input, displays available voices, starts generation, and plays the result.
2. **FastAPI application:** Validates requests, enforces limits, manages jobs, and coordinates processing.
3. **Voice catalog:** Stores metadata for approved voice references and trained models.
4. **Inference workers:** Execute OpenVoice and RVC processing in the appropriate environment.
5. **Temporary audio storage:** Holds input and output files only as long as necessary.

### Text-to-voice request flow

1. User enters text and selects a supported voice.
2. Frontend sends the request to the backend.
3. Backend validates the request and checks usage limits.
4. The selected base TTS model generates speech.
5. OpenVoice applies the reference speaker's vocal characteristics.
6. Backend returns a playable audio result.
7. User listens to and downloads the output.

### Voice-to-voice request flow

1. User uploads or records source speech.
2. Backend validates the recording and target model.
3. Audio is prepared for the selected RVC model.
4. RVC performs voice conversion.
5. Backend returns the converted audio.
6. User compares and downloads the result.

Long-running inference should use job IDs and status polling rather than keeping an HTTP request open indefinitely.

## 5. Free Usage and Deployment Strategy

The platform should be free for visitors, subject to fair-use limits and the available compute capacity.

### Development stage

- Run the frontend and backend locally on Windows.
- Install and validate the models independently.
- Start with one working target voice.
- Store generated files temporarily on the local machine.
- Avoid unnecessary databases and infrastructure until required.

### Public deployment stage

- Deploy the frontend to a suitable web-hosting service.
- Deploy the backend and inference workers to infrastructure compatible with the selected models.
- Use a GPU host if model performance and concurrency require it.
- Keep API keys in backend environment variables or a secret manager.
- Add usage limits, job timeouts, queue limits, and temporary-file cleanup.

Free hosting and inference services may have quotas, cold starts, queues, or restrictions. A public website does not guarantee unlimited free model inference.

Gemini, Groq, and OpenRouter free tiers may help with optional language tasks, but they do not replace the compute required to run OpenVoice and RVC. The service should degrade gracefully when any external quota is exhausted.

## 6. Security, Privacy, and Responsible Use

- Use voices that the operator owns, has permission to use, or is otherwise authorized to process.
- Do not provide a workflow intended for deceptive impersonation or fraudulent statements.
- Clearly label generated and converted audio as synthetic.
  > [!NOTE]
  > **Audio Provenance & Metadata Disclosure:** Generated and converted audio streams embed synthetic attribution metadata tags (`AI Synthesized Speech` / `AI-generated`). Cryptographic C2PA manifest signing (using PKI certificate authorities and cryptographic signatures) is not implemented in this local build; metadata tags are informational labels.
- Never expose API keys, internal model paths, or administrative endpoints to the browser.
- Validate uploaded files and reject unsupported or excessively large inputs.
- Restrict file access and prevent arbitrary filesystem paths from being supplied by users.
- Apply rate limits and resource quotas to reduce abuse and denial-of-service risks.
- Delete temporary uploads and generated files according to a documented retention policy.
- Avoid retaining raw reference recordings unless retention is necessary and explicitly disclosed.
- Review each model's license and the permissions attached to its voice data before public deployment.

## 8. Important Technical Constraints

- OpenVoice V2 does not itself supply a universal celebrity voice catalog.
- RVC conversion requires compatible target voice models.
- Text-to-speech quality depends on the base model and language support.
- Voice conversion quality depends on source audio, target model quality, and preprocessing.
- CPU inference may be slow; suitable GPU hardware can materially improve performance.
- Free external APIs and hosting are quota-limited.
- A public deployment must account for concurrent jobs, memory use, storage, and abuse prevention.
- Voice cloning permissions and model licensing must be evaluated independently.

Do not promise that any arbitrary voice, reference recording, or language will work perfectly.

## 9. Definition of Done

The first public version is complete when a visitor can:

1. Open the website.
2. Enter a script or upload an audio recording.
3. Choose a supported target voice.
4. Generate or convert audio.
5. View processing status and meaningful errors.
6. Play and download the output.
7. Use the application without supplying private API keys.

The service must enforce reasonable usage limits and disclose its supported voices, privacy practices, and limitations.

## 10. Guiding Principle

Build the AI pipelines first, then connect them to a polished interface. Do not start by building a large celebrity voice catalog, user accounts, payment infrastructure, or complicated cloud architecture.

The immediate goal is one reliable end-to-end voice-generation workflow. Once that works, expand the platform incrementally without compromising reliability, privacy, or the free-to-use objective.

## 12. Local Development & Launch Instructions

### Prerequisites
- **OS:** Windows 10/11 or Linux
- **Python:** 3.10.x with pip
- **Node.js:** v20.x or v22.x with npm
- **FFmpeg:** Installed and available in system `PATH` (`ffmpeg -version`)
- **GPU (Recommended):** NVIDIA GPU with CUDA 12.4+ (CPU fallback supported)

### Step 1: Backend Setup
```bash
# Navigate to backend directory
cd backend

# Create and activate virtual environment
python -m venv .venv
# On Windows PowerShell:
.venv\Scripts\Activate.ps1
# On Linux / macOS:
source .venv/bin/activate

# Install dependencies
pip install -r requirements.txt
pip install -r requirements-ml.txt

# Copy environment variables
cp .env.example .env

# Run database synchronization and launch backend ASGI server
python main.py
```
Backend will be live at `http://localhost:8000` with interactive API docs at `http://localhost:8000/docs`.

### Step 2: Frontend Setup
```bash
# Navigate to frontend directory
cd frontend

# Install Node dependencies
npm install

# Start Vite development server with proxy to backend
npm run dev
```
Open your browser at `http://localhost:3000` to access the AI Voice Studio interface.

### Running Test Suite
```bash
# Run full backend test suite (51 tests)
cd backend
pytest -v

# Run fast CI test suite (excluding slow model weights)
pytest -v -m "not slow"

# Typecheck and build frontend production bundle
cd frontend
npm run build
```

## 13. Docker Container Deployment

AI Voice Studio provides a production-hardened multi-stage Docker container with FFmpeg, libsndfile, non-root user execution, and automated healthchecks.

```bash
# Build the backend container image
docker build -t ai-voice-studio-backend:latest -f backend/Dockerfile backend/

# Run the container with GPU support
docker run -d \
  --name voice-studio \
  --gpus all \
  -p 8000:8000 \
  -v voice_studio_storage:/app/storage \
  ai-voice-studio-backend:latest

# Check container health status
curl http://localhost:8000/v1/health
```

## 14. Verified Multilingual Capabilities & Performance

| Language | ISO | Engine Pipeline | Base TTS Model | Tone Color Converter | Tested Pronunciation & Unicode |
|---|---|---|---|---|---|
| **English** | `en` | MeloTTS + OpenVoice V2 | `myshell-ai/MeloTTS-English` | OpenVoice V2 Tone Converter | Latin script, standard English phonetics |
| **Hindi** | `hi` | Meta MMS-TTS + OpenVoice V2 | `facebook/mms-tts-hin` (VITS) | OpenVoice V2 Tone Converter | Devanagari script + Romanized Hinglish |
| **Marathi** | `mr` | Meta MMS-TTS + OpenVoice V2 | `facebook/mms-tts-mar` (VITS) | OpenVoice V2 Tone Converter | Devanagari script |

### Verified Hardware Metrics (NVIDIA RTX 3050 6GB)
- **Base TTS Synthesis (EN):** ~1.8 seconds
- **Base TTS Synthesis (HI / MR):** ~3.5 seconds
- **OpenVoice V2 Tone Conversion:** ~5.1 seconds
- **RVC Voice Conversion (RMVPE):** ~4.2 seconds
- **Peak GPU VRAM Usage:** 987 MB (MeloTTS + OpenVoice) / ~1.4 GB (RVC RMVPE)
- **Memory Safety:** OpenVoice and RVC models perform mutual GPU unloading to prevent out-of-memory crashes on 6GB VRAM.

## 15. API Reference Summary

| Method | Path | Description | Response Status |
|---|---|---|---|
| `GET` | `/v1/health` | Healthcheck and engine version | `200 OK` |
| `GET` | `/v1/config/public` | Public rate limits, character, and duration limits | `200 OK` |
| `GET` | `/v1/voices` | List verified public voices (masks filesystem paths) | `200 OK` |
| `GET` | `/v1/voices/{id}` | Detailed voice profile | `200 OK` / `404 Not Found` |
| `GET` | `/v1/voices/{id}/preview` | Stream preview audio sample | `200 OK` (audio/wav) |
| `POST` | `/v1/tts` | Enqueue standard multilingual TTS job | `202 Accepted` |
| `POST` | `/v1/tts/custom` | Enqueue custom voice clone TTS job (multipart audio) | `202 Accepted` / `400 Bad Request` |
| `POST` | `/v1/vc` | Enqueue RVC voice conversion job (multipart audio) | `202 Accepted` / `400 Bad Request` |
| `POST` | `/v1/text/cleanup` | Normalize script abbreviations, numbers, and currency | `200 OK` |
| `GET` | `/v1/jobs/{id}` | Poll asynchronous job status and progress | `200 OK` / `404 Not Found` |
| `DELETE` | `/v1/jobs/{id}` | Cancel/delete job and purge disk artifacts | `200 OK` |
| `GET` | `/v1/audio/{id}/output` | Stream completed audio (`?format=wav` or `?format=mp3`) | `200 OK` |
| `GET` | `/v1/audio/{id}/source` | Download uploaded source audio | `200 OK` |
